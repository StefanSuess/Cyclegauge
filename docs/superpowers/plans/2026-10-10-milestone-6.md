# Milestone 6 — cross-platform support (0.6.0), final revised plan

## Status and context

**Implementation status (2026-10-11):** Task 0, Task 1A and the Task 1B tooling are done on `feature/cross-platform`; see `docs/milestone-6-validation.md`. Windows ACL proof-of-concept accepted as technically viable on Windows Server; SC1 remains open. Architecture and decisions D1–D7 were **approved on 2026-10-11 with three refinements**, all incorporated here:

- **Refinement A — Windows directory creation** (section 3): create-then-lock-down alone is not accepted. Creation must be private from birth via a verified private parent; creation-time descriptors are evaluated as an alternative. No claim that all races are eliminated; Windows stays fail closed if the proof-of-concept cannot establish the design.
- **Refinement B — RHEL 9 network storage** (section 4): no assumption that the corporate home is local. Network storage stays rejected; the policy is finalised only after the environment survey, with a secure configurable local location designed if needed.
- **Refinement C — VSIX verification** (section 7): compare extracted allowlisted contents and per-file hashes; never require identical ZIP bytes.

Mandatory targets: **Windows 11**, **RHEL 9**, **macOS** (preserve). Ubuntu and Debian are broad-compatibility targets. Correction retained from the previous revision: Kiro documents **no glibc requirement for the IDE** (the 2.34+ statement is for the CLI); the official tarball is installed on RHEL 9 **[reported]**, so compatibility is established from the installed binary and runtime.

Baseline: `main` at `9ac4c0d`, tag `v0.5.1`, 184/184 tests on macOS (local Node 26.11.1; declared floor 24.13). Work goes on `feature/cross-platform`; `.agents/` is never staged.

Evidence labels: **[observed]** in this repo, **[documented]** vendor docs, **[reported]** by the project owner, **[inferred]**, **[unverified]**.

## 2. Architecture: portable first, OS logic isolated

Unchanged: `projection.ts`, `time.ts`, `decimal.ts`, `history.ts`, `forecast.ts`, `view.ts`, `src/cost/*`, `chart*.ts`, `cost-*.ts`, collector semantics, Store schema v1 (no migration), CLI billing contract. No runtime dependency, **no native addon**, one platform-neutral VSIX.

- **Three branches only:** `darwin`, `win32`, everything else (XDG/POSIX). No distribution sniffing.
- **The POSIX storage guard spawns no processes** (Node `fs` only); only Windows launches system tools. This removes one dependency — the guard itself needs no permission to execute helper programs. It does **not** mean SELinux, `noexec` mounts or fapolicyd cannot affect Kiro IDE execution, extension installation or extension loading in general; those remain part of the native RHEL 9 verification (section 4).
- **Discover the running IDE's own root (D2):** explicit `sourceRoot` → root derived from `context.logUri` (validated shape `…/logs/<run>/<window>/exthost/<id>`) → platform default. Reads a property, creates nothing. CLI keeps defaults plus `--source-root`.
- **Capability probes, not version checks:** `node:sqlite` loadable; `JSON.parse` reviver source text available (needed by `projection.ts` for exact decimals). Missing either gives a fixed unavailable code.

## 3. Windows 11 track — ACL security model

**Threat model.** Other non-administrative local accounts cannot read the store — parity with POSIX `0700`/`0600`. Administrators, SYSTEM, same-user processes and offline access are out of scope. No encryption claim.

**Trusted principals** `T = {current user, SYSTEM S-1-5-18, Administrators S-1-5-32-544}`. SIDs are private: memory only.

**Store invariant, checked on every open before the key or database is touched:**

| Object | Required |
| --- | --- |
| Storage directory | Local fixed volume (UNC/mapped rejected); no reparse point of any tag; owner ∈ T; DACL present and **protected**; only plain allow ACEs with trustee ∈ T; inheritable full control for the current user |
| Immediate parent (SC1 decision, 2026-10-11) | Directory, no reparse point; owner ∈ T; DACL present; only plain allow ACEs with trustee ∈ T; inheritable full control for the current user. **Not required to be protected** (a default `%LOCALAPPDATA%` inherits its DACL); upstream safety comes from the ancestor rule |
| `device.key`, `usage.sqlite`, `-journal`/`-wal`/`-shm` | Regular file; `nlink === 1`; no reparse point; owner ∈ T; every explicit **or inherited** ACE is a plain allow ACE with trustee ∈ T; current user has full control |

Everything else fails closed with a fixed code: NULL/missing DACL, deny/object/callback ACEs, other trustees, unknown SDDL tokens, tool missing, timeout, unexpected output.

### Safe initial creation (Refinement A)

Why create-then-lock-down is insufficient on its own: Windows files inherit their protection from the directory, unlike POSIX where each file is created with an explicit mode. A directory born with a broad inherited DACL, or a directory swapped underneath us, could therefore expose files created in it.

**Candidate protocol — private from birth via a verified private parent:**

1. **Safe-path precondition.** Every existing ancestor up to the volume root is a real directory (no reparse point), has a trusted owner (T plus the Windows installer service for system directories), and grants **no principal outside T** a right that allows replacing a child or re-securing the directory: delete, delete-child, write-DAC, write-owner or full control. Deny ACEs are given no credit. This is the Windows analogue of OpenSSH's ancestor ownership check.
2. **Verified private parent.** The immediate parent must pass the T-only, safely inheritable parent rule in the table above (SC1 decision 2026-10-11: protection is required of the storage directory, not of the parent; a parent that inherits its DACL is acceptable when every actual trustee is in T and the ancestor rule holds). A child created there inherits only T entries at the moment of creation, by documented object-creation semantics **[documented]** — there is no interval in which it is broader.
3. **Single-level, non-recursive create.** If the name already exists, switch to verify-only; never adopt, repair or re-own.
4. **Protect.** Convert to a protected DACL so later parent changes cannot propagate. Requirement: every intermediate state is T-only or narrower.
5. **Verify** the invariant **and emptiness**; only then exclusive-create key and database; verify each file's descriptor before first use and before any billing data is written.

The default `%LOCALAPPDATA%\EasyKiroGauge` satisfied steps 1–2 on the runner profile chains of Windows Server 2022/2025 **[observed]**; a Windows 11 client profile is still **[inferred]** pending the native run. A configured `storageRoot` whose parent is not private fails closed with a fixed code; the remedy is choosing a location under a private directory.

**Alternative to evaluate, not promised:** creation-time security descriptor through PowerShell's .NET directory API. It is atomic by API contract but relies on .NET method calls, which Constrained Language Mode blocks **[documented]**. Adopted only if the proof-of-concept shows it works and is worth a second code path.

**What is and is not claimed:**
- Claimed, if the proof-of-concept confirms it: against principals outside T, the directory and its files are never observable with a broader DACL, and a swapped ancestor is excluded by the safe-path rule.
- **Not claimed:** elimination of all races. All checks are path-based (Node has no handle-relative or handle-based descriptor APIs), so a member of T or a same-user process can interfere, and filter drivers are not modelled. These are stated as residual limitations.
- Atomicity of inheritance rests on Microsoft's documentation; the proof-of-concept can show resulting states, not observe instants.

**Mechanism (D1, approved).** System executables by absolute `System32` path — `whoami.exe`, `icacls.exe`, Windows PowerShell `Get-Acl` (cmdlets and property reads only) — no shell, paths via environment variable, timeout; one batched read for ancestors, directory and files. Decision logic lives in `sddl.ts`. A native addon needs separate approval.

**Proof-of-concept (Task 1A) must establish, on a Windows runner with synthetic paths:**
1. Current-user SID retrieval, locale-independent.
2. Descriptor reads for ancestors, directory and files without elevation, including under the PowerShell lockdown test switch.
3. A child created in a T-only parent shows only inherited T entries immediately after creation.
4. The protect step never yields a state broader than T (descriptor read after each operation).
5. Typical default-profile ancestors pass the safe-path rule; deliberately loosened ancestors and parents are rejected.
6. Junction, 8.3 name, `nlink` and `bigint` identity behaviour as assumed.
7. Launch cost (budget p95 < 1 s; otherwise async `Store.open()`, never a weaker check).

**If any of 1–5 cannot be established, the `win32` fail-closed throw stays and 0.6.0 does not claim Windows 11.**

**Verification.** Pure table tests on all OSes (accept and reject per rule, rights masks, malformed input); real-NTFS tamper suite on runners (extra trustees, inheritance re-enabled, deny ACE, foreign owner, junction, hard link, planted sidecar, non-empty at creation, loose parent, loose ancestor — each rejected, nothing modified); native Windows 11 checks in section 7.

### Storage policy (Refinement B) — provisional until R0, finalised at SC1

- **Fixed now:** storage on a known network or cluster filesystem (NFS, SMB/CIFS, FUSE remotes, Ceph, Lustre, GPFS, AFS, 9p and similar) is **rejected with a fixed code**. Mode bits cannot prove privacy there and SQLite locking is not dependable. Filesystems that do not honour POSIX modes fail the existing exact-mode check on their own.
- **No silent relocation.** The extension never picks a fallback location by itself; that would split history and surprise the user.
- **Source on a network filesystem is allowed read-only**, flagged with a quality code; polling remains authoritative because attribute caching and inotify are weaker there.
- **If R0 shows a networked home:** the existing `storageRoot` / `--store-dir` setting is the configurable local location. The design to finalise at SC1, without weakening the model: same `0700` directory and `0600` files owned by the user, no links in the path, plus an ancestor rule for locations outside the home (each ancestor owned by root or the user and not group/world-writable unless sticky), a squat-safe create (exclusive, pre-existing foreign directory rejected), and explicit handling of volatile (tmpfs, cleared at logout) and age-cleaned (`/var/tmp`-style) locations — at minimum a persistent warning code, possibly rejection.
- **Undecided until R0:** whether a suitable local persistent location exists on the managed machine at all. If none does, RHEL 9 cannot reach L6 and the gate fails honestly; that outcome is reported, not engineered around.
- The ancestor rule would be new POSIX guard behaviour; it is adopted only with the SC1 decision and must leave macOS defaults passing unchanged.

### VSIX verification (Refinement C)

- **One release artifact.** The VSIX is built once in a designated job. Every native acceptance run and the release use that exact file, identified by its SHA-256. Functional equivalence across OSes comes from installing the same artifact, not from rebuilding.
- **Content, not container.** `scripts/verify-vsix.mjs` reads the archive entries with Node only, asserts the entry list equals the allowlist (manifest, README, `dist/extension.cjs` plus the packaging metadata), and emits a per-file SHA-256 manifest of the **extracted** contents.
- **Cross-OS builds are a reproducibility signal.** Each OS job also builds and emits the same manifest; a compare job checks per-file hashes of the payload files. A difference in the bundle is investigated; differences in ZIP bytes, timestamps, ordering or compression are ignored. Deterministic archive generation is neither assumed nor required.
- **Bundle smoke on every OS.** `scripts/smoke-bundle.mjs` loads the extracted `dist/extension.cjs` from the release artifact with a stub `vscode` module against an invented root and asserts activation and status output — so C2 covers the shipped bundle, not only the TypeScript sources.

**New synthetic cases:** path defaults from injected env; `rootFromLogUri` shapes; containment across drives/case; links and junctions at every level; rotation/truncation during read; CRLF; two processes on one store; missing SQLite or reviver capability; failing watcher; ACL shim timeout/garbage; full SDDL and rights-mask tables; safe-path accept/reject; filesystem classification from invented mountinfo text.

**Windows 11 native:** installs and activates; diagnostics recorded; store under `%LOCALAPPDATA%` with ancestors passing the safe-path rule; **a second standard account is denied** on directory, key, database and a live sidecar (lab VM acceptable if the managed machine cannot create accounts); each tamper yields the fixed code with nothing repaired; Kiro's rotation and old-log cleanup unaffected, its ACLs and timestamps unchanged; profile name with space and non-ASCII; two windows; sleep/resume; update within 60 s; managed-machine restrictions recorded as tested or untested.

**RHEL 9 native:** ladder L0–L8. **macOS:** reinstall, existing store opens without migration, same UI, no new warnings.

## 8. Security checkpoints and release gates

- **SC1** — proof-of-concept items 1–7 and the RHEL 9 survey reviewed; Windows enablement confirmed or left fail closed; storage policy finalised. Before any enforcement code.
- **SC2** — the diff removing the Windows fail-closed throw: every rejection rule and each creation step mapped to a test; no path by which Kiro files reach an ACL tool; no SID/path in output; residual-race statement reviewed for accuracy.
- **SC3** — workflow permissions and pinning; VSIX content manifest equals the allowlist; no fixture derived from real data.
- **SC4** — evidence documents contain no private or workplace data; every support statement maps to recorded evidence at the stated level.

**v0.6.0 may claim Windows 11 and RHEL 9 support only when:** CI green on the release commit; SC1–SC4 closed; macOS regression passed natively; **Windows 11 at C3 + C4**; **RHEL 9 at C3 + C4 (L0–L8, SELinux Enforcing)**; documentation carries the four-level matrix. If a mandatory gate cannot be completed, the release is held and the decision returns to the project owner.

**Limitations to state openly:** Windows checks are path-based and do not eliminate all races; RHEL is not on Kiro's listed distributions; RHEL 9 SELinux evidence is functional-only unless audit access exists; network storage is rejected and a managed machine may offer no acceptable local location; Windows Server CI is not Windows 11; Constrained Language Mode/EDR/fapolicyd outcomes may be untested; elevated Kiro, ReFS/Dev Drive, WSL/remote hosts, Flatpak/Snap are unverified or rejected; a profile or ancestor named `Kiro` fails closed; untested architectures are not claimed; administrators/root can read the store.
