# Milestone 4 Cost Optimizer Implementation Plan

> **For agentic workers:** After explicit approval, use superpowers:executing-plans for native task-by-task execution, or superpowers:subagent-driven-development if the user chooses that method. Steps use checkbox syntax. **This plan is not implementation authorization.**

**Goal:** Compare evidence-backed Kiro subscription strategies and estimated new expenditure, with honest conditional results when billing or user inputs are incomplete.

**Architecture:** A pure TypeScript catalog/demand/simulation/comparison core consumes explicit billing inputs and qualified forecast evidence. A thin extension adapter collects manual inputs and renders the result in the existing script-disabled detail view. No new collector or service.

**Tech Stack:** Existing TypeScript, Node.js >=24.13, built-in node:test, BigInt rational arithmetic, VS Code native input APIs, existing esbuild/VSIX tooling; no new runtime dependency.

**Spec:** [Milestone 4 design and billing evidence](../../cost-optimizer-roadmap.md). [Milestone 5 dashboard](../../milestone-5-visual-dashboard.md) remains documentation-only.

## Global constraints

- Execution status: user accepted M4A (113 tests) and approved M4B Task 5 plus the performance prerequisite on 2026-10-10. All five tasks are implemented and validated; see M4B evidence. No automatic commits. See [M4A evidence](../../milestone-4a-validation.md).
- Follow AGENTS.md privacy/read-only requirements; synthetic tests only. No authenticated Kiro calls, telemetry, purchases or subscription mutations.
- Preserve collector behavior, Store schema v1, CLI contract, and forecast schema/policy v2. No Kiro SQLite/session/Crew adapters.
- Amounts use decimal strings and exact internal rational arithmetic. Null means unknown, never zero. No raw or derived identities in engine results or diagnostics.
- Support five consumer tiers and four Enterprise paid tiers through separate billing rules. Custom/GovCloud exact recommendations remain unavailable without reviewed rules.
- Catalog facts must be reverified publicly before executable pricing is added. Unknown pack increments, slot recycling, restoration and proration details remain gates.
- Default sensitivity is 75% / 100% / 125% of future demand, explicitly hypothetical. It is not a confidence interval.
- 1/3/6 months means complete billing cycles beginning at the next verified reset; show the current partial cycle separately.
- Manual profiles are session-only and cleared on account change, ambiguity or extension restart. No sync or persistence migration.
- No Milestone 5 implementation, chart library or generic solver.

## Review focus

1. **Almost equal costs:** rounded rate or money text must not decide the cheaper plan. Task 2/3 exact-boundary tests.
2. **Inventory changes between snapshots and manual input:** matching plan names do not establish a shared as-of balance. Task 2 stale/misaligned-anchor tests.
3. **First-paid and returning-Free users:** existing paid-upgrade formulas cannot become universal. Task 1/3 cohort tests.
4. **An apparently cheap but infeasible plan:** exhausted Free capacity or Enterprise quota cannot win by leaving usage unserved. Task 3/4 baseline tests.
5. **Account changes while inputs are open:** manual profile must not leak to another account, including a canceled editor or a late refresh. Task 5 integration tests.
