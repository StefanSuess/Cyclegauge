# Milestone 1 Implementation Plan

**Goal:** Independently usable read-only CREDIT log collector and CLI.
**Authority:** SPEC.md, ARCHITECTURE.md, ROADMAP.md and the user's explicit implementation request.
**Execution:** Inline, in the supplied checkout. No commits or production data reads needed.
**Stack:** TypeScript, Node.js 24.13+ (built-in SQLite and TypeScript stripping), Node test runner, TypeScript compiler for static checks.

## Constraints and design

Only enumerate logs/<run>/<window>/exthost/kiro.kiroAgent/q-client.log (and numeric rotated suffixes). Open read-only, reject symlinks, bound lines, defer unterminated tails. Do not scan sessions or databases. Full rescans favor correctness under same-size replacement over cursor optimization; durable private per-file fingerprints/lengths record rotation/truncation evidence. Incomplete/conflicting observations cannot fabricate current values.

Store only allowlisted billing projections and keyed opaque identity/deduplication/source tokens in app-owned SQLite. Persist a device-local key with owner permissions. Reject repository/source overlap and symlinked storage. Use a transaction for each import; serialization is provided by SQLite transactions. Unknown accounts remain isolated; CLI cannot assert which login is currently active. Keep timestamp offsets, use an explicit IANA source timezone for offset-free timestamps, reject DST ambiguity. Decimal strings and BigInt arithmetic preserve numeric token precision.

## Review focus
