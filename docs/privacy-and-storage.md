# Privacy, storage and reliability

The short version is in the README. This page keeps the full detail.

## Principles

- **Read-only.** Kiro's files and databases are never modified, and Kiro is never started or called.
- **Local only.** No telemetry and no network transmission: the extension contains no network code. Derived numbers are kept in the extension's own private directory.
- **Minimal data.** Complete log lines are processed in memory while parsing, but only explicitly allowlisted billing fields are extracted and persisted. Raw account identifiers are not stored; pseudonymous identifiers derived with a device-local key (HMAC) are used locally to separate accounts. Prompts, code, conversations, tool data and credentials are dropped after parsing and never stored or shown, and diagnostics contain only fixed codes and counts.

## Storage and reliability

The adapter temporarily parses a bounded complete log envelope, projects only validated billing fields and a narrowly scoped `output.userInfo.userId` for in-memory continuity, then drops the envelope. Identity is HMAC-partitioned with a device-local 32-byte key; raw identity is never persisted. Private source/deduplication tokens stay in owned SQLite and are absent from CLI output. On POSIX, device key and database use mode 0600; the dedicated directory uses 0700. The extension stores this in the editor's per-extension storage folder, as other extensions do; it never writes among Kiro's logs. On Windows, that default (and the CLI's `%LOCALAPPDATA%` default) relies on the user profile's own permissions and is not separately verified (a portable install or a custom `--user-data-dir` on a shared drive is not protected by them). A chosen storage location is: a local NTFS directory is created with a protected owner-only inheritable DACL before writing sensitive data; existing directory, key, database and sidecar ownership/access rules are verified (files created by an elevated process may be owned by Administrators; the access list still names only the user). Unsafe existing ACLs are never repaired automatically. See [platform verification](platform-verification.md) for restrictions. Unknown fields, raw records, error representations, prompts and source paths are never written to the store or diagnostics. There is no telemetry or network code.

Full bounded rescans plus durable deduplication protect restarts, rotation, truncation and same-size replacement. Content/identity fingerprints and source lengths remain private. `source_changed` means content/identity changed or length shrank, including ordinary append; it does not prove lost usage. Partial trailing lines are deferred until a complete newline. A changing source read is discarded. Each stable source import is transactional; concurrent store connections serialize via SQLite transactions. A failed later file can leave earlier successful file transactions durable and safe to re-import.

Bounds: 256 KiB per line, 64 MiB per file, 10,000 accepted records per file, at most 1,000 discovered files and 1,000 run/window entries per level. Oversized files, too many records, and malformed/unsupported records produce fixed codes. These are conservative operational limits, not verified Kiro limits. The extension adds a watcher and polling fallback. SQLite schema version 1 supports this collector only. The store has an ordered migration path for future versions; a store written by a newer Cyclegauge version is refused (`STORAGE_NEWER`) and never modified. Import evidence keeps at most 10,000 rows, and unchanged codes refresh the latest row's time instead of adding rows. Snapshot history is not pruned. Keep `device.key` and `usage.sqlite` together; loss or corruption fails unavailable rather than inventing a balance. Local snapshots contain private billing amounts: keep them local and do not attach the store to bug reports.

## What is read, honestly

The files the extension opens (`q-client.log` and rotations under Kiro's `logs/` folder) can contain more than billing data, including content Kiro logged. The extension parses each complete log line in memory, keeps only allowlisted billing fields and a narrowly scoped user identifier used for in-memory continuity, and discards the rest. That identifier is stored only as a device-local HMAC (a pseudonymous partition key), never in raw form. It is still derived from account identity, so treat the storage folder as private and never attach it to bug reports. The credit view runs one bundled script (injected inline with a per-load nonce, under a content security policy that allows no network connection, no frames and no other script or style, and with Trusted Types enforced, see the [dashboard design](wp6-dashboard-design.md)); it talks to the extension only through a validated, allowlisted message protocol. Its only command links are five Cyclegauge commands (Cost Advisor, check workspace, show workspace audit, share, report a problem), enabled through the webview's command allowlist and carrying no arguments. Its footer holds three fixed web addresses (Open VSX reviews, the GitHub repository, Ko-fi); they open only when you click them, with no tracking parameters. Its Workspace check card shows only a count and a time, never a folder name or path.

**Session hints (macOS observed, Windows and Linux enabled but not yet verified natively; on by default).** This is a third kind of read, separate from the account-usage logs and from the Store. Every minute (first after about 15 seconds) in a local Kiro window on macOS, Windows or Linux, with `cyclegauge.sessionHints` on, Cyclegauge looks for the newest IDE session of your open folder under `~/.kiro/sessions` (the `.kiro/sessions` folder of your home folder; on Windows `%USERPROFILE%`). To do so it parses up to 20 of the most recently changed sessions' `session.json` files (each whole, in memory, including titles and workspace paths) to find the newest session of your open folder (each at most 64 KiB), then loads up to the last 256 KiB of that session's `messages.jsonl` into memory, which can contain your prompts and Kiro's replies; a larger file is read by its tail only. It keeps only that session's model identifier, context percentage and time, compares workspace paths only (as strings, no filesystem call) to find your open folder, and never stores, logs, shows or sends anything else. Decoded strings of the lines that passed through memory cannot be erased by JavaScript; the raw read buffers are zero-filled after use. Nothing is persisted (the state of which notice was shown lives in memory and resets with the window), nothing is written, and Kiro's files are opened read-only.

How it is bounded: the root is fixed (`~/.kiro/sessions`; there is no setting to change it, and a symlink at `~/.kiro` or any folder on the way makes the feature stay silent), at most 200 entries per folder level are listed (more than 200 workspace folders gives the fixed code `listing_capped` and silence; one workspace folder with more than 200 sessions is skipped and counted, the other folders are still checked, and if no session is found the code is `listing_capped`; Copy Diagnostics shows the count as `session_hint_capped`), at most 20 `session.json` files are opened per check, a session counts only when its own `lastModifiedAt` agrees with the file time, and a file that changes while it is read is discarded. A check has a time budget of half a second: after that it gives up with the fixed code `aborted` (a hanging filesystem call is abandoned and its handle closed in the background). Of the conversation lines only newline-terminated lines of at most 4 KiB that contain both `"session_metadata"` and `"contextUsage"` are decoded; all must then have the exact event shape or they are dropped (a user message that happens to contain both words is decoded briefly and dropped). Errors are mapped to a closed list of codes (`ok`, `disabled`, `unsupported_platform`, `no_root`, `listing_capped`, `no_match`, `unsafe`, `changed`, `aborted`, `unsupported_schema`, `invalid_shape`, `no_candidate`, `out_of_range`, `stale`, `error`); the text of an error is never logged. Diagnostics show only the last code, a count of notices and `session_hint_capped`, a count of workspace folders skipped as over-full.

The setting is user-level (application scope): a workspace or folder `settings.json` cannot change it. When it is off, on a platform other than macOS, Windows or Linux, in a remote, WSL or SSH window, or without a local folder, Cyclegauge makes no filesystem call for this feature at all. The files are Kiro's undocumented implementation detail; the field semantics were observed on one macOS installation on 2026-10-18 ([data proof](wp11-13-data-proof.md)) and Kiro can change them without notice, in which case the feature goes silent. On Windows and Linux the folder location and the path format in the session files are unverified; if they differ, the feature stays silent (a symlink or junction anywhere on the way to the folder also keeps it silent). The model table in the extension is dated 2026-10-18 (Kiro's published model table: 22 models besides Auto) and is reviewed with each Kiro model release. Only three identifiers were seen in real session files and two more appear in Kiro's settings documentation; the rest are derived from the published names and may not match what Kiro writes, in which case no hint appears.

**Workspace audit.** When you run **Cyclegauge: Audit Kiro Workspace**, automatically only if you set `cyclegauge.auditAutomatically` in your user settings (with `onOpenAndChanges` also after a file matching the audit's name patterns appears; the editor's file watcher reports only names, and the paths of new files are kept in memory until the next check), or silently again after you change the ignore rules of a workspace you checked in this window, the extension walks one trusted local workspace folder reading file names and sizes, plus the ignore files listed in Agent Ignore Files. It does not read other file contents or global ignore files itself (a manual audit additionally runs the Steering and Hook review below, with its own bounded reads), writes no workspace or settings file and sends nothing; **Exclude from Kiro** only prepares an unsaved change that you save yourself, and the clipboard is used only for Copy .kiroignore lines. Folders overlapping Kiro data or Cyclegauge storage, credential folders and broad roots are refused. Results are shown in a native view. In the editor's per-workspace storage Cyclegauge keeps only the last audit date, a snooze date, a do-not-remind flag and salted SHA-256 hashes of items you chose to hide, never paths.

**Separate Steering and Hook review.** **Cyclegauge: Review Kiro Steering and Hooks** is its own explicit command (in the Command Palette; the Audit view's one **Check** button runs it together with the audit); it runs when you click it, together with every manual workspace audit (not with the audit's silent re-runs), or automatically only if you turn on the user setting `cyclegauge.configReviewAutomatically` (off by default; only your own user value counts, never a workspace's): then once per window when a trusted workspace opens and, in `onOpenAndChanges`, when root `AGENTS.md`, `.kiro/steering/*.md` or `.kiro/hooks/*.json` change, reading nothing else. Automatic runs use the same allowlist and limits, at most 20 per window. The change watcher's handler makes no filesystem call and keeps no changed path. The filename audit's silent re-runs, its reminder prompt and its watcher never invoke it; only a manual audit does, with exactly the manual command's guards and reads. Each of up to eight trusted local roots passes the same folder guard, with real-path deduplication. The allowlist is root `AGENTS.md` (size only), `.kiro/steering/*.md` (first few bytes, and up to 2 KiB only when the file starts with front matter) and `.kiro/hooks/*.json` (parsed up to 64 KiB per file). Hook names are read, capped at 60 code points before escaping, and shown only in sidebar labels. Steering body, pattern, matcher, prompt and command text is not kept or shown; previews contain fixed guidance and escaped relative file names only, with hook ordinals instead of names. Global home-folder configuration, nested `AGENTS.md`, legacy hooks, custom agent resources and cloud configuration are not checked. Nothing is executed, copied to the clipboard or sent, and Cyclegauge itself writes no workspace file. Its apply actions (**Review changes…** for **Load only when needed** and **Run only manually**, one item or a whole group; **Disable**; **Narrow the pattern**) open the real Steering or Hook file in the editor and prepare small **unsaved** edits (or a selection) that you review in the editor's own change preview and then save, as **Exclude from Kiro** does for the audit (its **Review changes…** uses the same preview, with a fixed why-and-alternatives text per change that holds no path or file content); the file is first checked to be unchanged since the review and Cyclegauge's code reads no file text beyond the approved Steering prefix (up to 2 KiB) and Hook JSON (up to 64 KiB); the editor loads the opened file as it does when you open it yourself. Files not encoded as UTF-8 may be re-encoded by the editor when you save the prepared edit, so check the change before saving. For that check the review keeps, in memory only, a size, a modification time and a SHA-256 digest per file it read (no text, no file name inside the value). Nothing is prepared in an untrusted workspace, when the editor saves automatically or when the file has unsaved changes. Saving a Steering or Hook file that Cyclegauge prepared an edit in starts one manual-equivalent review (approved 2026-10-20): the same guards, reads, allowlist and limits as the manual command, only for a trusted workspace and a checked local root, single-flight (a save during a running review is answered by exactly one more review when it finishes), not counted toward the automatic cap, without moving focus and without the one-time offer. No other save starts it, and no watcher is added. Cyclegauge keeps the paths of the files it prepared an edit in (from the last successful editor edit, at most 500), in memory only, until the file is saved, closed or reverted; they are never stored, shown, logged or sent, and this adds no read. Review results, the automatic mode's seen finding kinds, run counters and "new this session" markers live only in memory, separate from the audit, its reminder state, the dashboard's Workspace card and support prompts. The only storage key is `cyclegauge.configReview.offered.v1` in the editor's global state (not the workspace, not Settings Sync): `true` once the one-time offer to turn on automatic review was shown, holding no data; a value of an unknown shape counts as shown and is never overwritten, and **Cyclegauge: Reset Support Prompts and Summary** clears it. The offer writes your user setting only when you click **Turn on**, and is not shown when `cyclegauge.supportPrompts` is off. Untitled suggestion documents (only for combined-size and overlapping-hook findings) can survive editor hot exit, so they contain no read content or hook names; an unsaved edit in a real file is the editor's own document, which you save or discard.

**Community prompts.** Cyclegauge may ask once per window, inside Kiro, whether you'd rate or support it (turn off with the user setting `cyclegauge.supportPrompts`), and shows a one-time note in editors that are not Kiro. The prompt offers **Rate**, **Support** and **Later**; rating and support links open only when clicked. The legacy `cyclegauge.support.never.v1` flag continues to suppress prompts for users who previously selected **Don't ask again**, and Reset Support Prompts clears it. **Cyclegauge: Share Cyclegauge** copies a fixed text with the Open VSX link and nothing about you. In the editor's global state (not the workspace) Cyclegauge keeps only these keys: `cyclegauge.support.firstSeen.v1` (UTC date of first use), `cyclegauge.support.next.v1` (UTC date before which it does not ask), `cyclegauge.support.never.v1` (legacy true value suppresses prompts), `cyclegauge.support.valueSeen.v1` (true once a forecast or audit finding was shown) `cyclegauge.support.detailDays.v1` (at most three distinct UTC dates when Show Account Credits was opened), `cyclegauge.support.advisorUsed.v1` (true after a completed Advisor review, never its answers) and `cyclegauge.notKiro.shown.v1` (true once the not-Kiro note was shown). The first-minute walkthrough adds `cyclegauge.walkthrough.shown.v1` (true once it was opened or skipped for an existing user; written before it opens; not yet verified in native Kiro, and an editor without walkthrough support simply ignores the open request). The saved-exclusion signal keeps the prepared ignore edit and its target only in memory until the matching save; it persists no file path or content and the one-minute timer does not survive a reload. Reset Support Prompts clears every support key. An explicitly enabled isolated synthetic demo can treat first use as yesterday for native testing; this does not change ordinary profiles or disable snoozes. There is no telemetry; external links are opened with the editor's own opener only after you click a button or link.

**Budget warnings.** Inside Kiro (never in the extension tests), Cyclegauge may show one notice per window when your fresh, reported usage reaches `cyclegauge.budgetWarningPercent` of the limit (default 80, 0 = off), a qualified forecast reaches the limit before the reset, or the limit is reached; turn them off with the user setting `cyclegauge.budgetWarnings` or the notice's **Turn off** button, which writes only that setting. In the editor's global state (not the workspace) it keeps one key, `cyclegauge.budgetWarning.v1`, holding only the billing cycle (the observed reset time as an ISO string) and a list of which of `limit`, `forecast`, `percent` and `rightsize` were already shown in it. The right-sizing hint (Cost Advisor estimate and stored account history) and the next-larger-plan comparison (bundled price list) are computed in memory and store nothing. It is written before a notice is shown (a failed write means no notice); no amounts, identifiers or paths are stored, and nothing is sent anywhere. The modelled overage figure in the credit view and notices is computed in memory from the reported numbers and the bundled price list and is never stored.

**Your Cyclegauge summary.** When you save a prepared **Exclude from Kiro** change while a billing cycle is observed, Cyclegauge adds the count of accepted items, how many were possible secrets and their total size (marked as a lower bound when a size is unknown) to one key in the editor's global state (not the workspace, not Settings Sync), `cyclegauge.results.v1`. It holds at most the two most recent cycles with saved exclusions as `{ cycle, bytes, bytesLowerBound, items, secrets }`, where `cycle` is the billing reset time; no path, name or identifier is stored. A value of an unknown shape is shown as unknown and never overwritten; **Cyclegauge: Reset Support Prompts** clears it. The observed use trend in the same section is computed in memory from the stored account history and is never stored.

**Your Kiro cycle (recap, image and CSV).** The first time a new billing cycle is observed and the cycle before it has an evidence-backed start and end, the credit view shows a dismissible "Your Kiro cycle" card built from stored account history only: credits used, whether they lasted until the reset (yes only with an update below the limit in the last 6 hours before it, no only if usage at or above the limit was observed, otherwise unknown), the observed use compared with the cycle before (or "not comparable"), the exclusions you saved in that cycle (from `cyclegauge.results.v1`) and the busiest observed UTC day, labelled as a partial observation. The Open VSX link appears as plain text and is left out when `cyclegauge.supportPrompts` is off. In the editor's global state (not the workspace, not Settings Sync) it keeps one key, `cyclegauge.recap.v1`, `{ cycle, state }` where `cycle` is the newly observed billing reset time and `state` is `shown` or `dismissed`; no path, name or identifier is stored. A value of an unknown shape hides the card and is never overwritten; **Cyclegauge: Reset Support Prompts and Summary** clears it. **Save image…**, **Export CSV…** and **Copy text** are the only ways the card or your history leave the view. Files are written only after you confirm the editor's save dialog (offered in Downloads, otherwise your home folder, never the workspace), only to `file:` targets, and never into Cyclegauge's own storage, a configured or default Kiro source or data folder, or any folder named `.kiro` or `kiro-cli`; links and special files are refused, and the file is written to a temporary file in the checked folder and renamed over the target (removed on failure). Before saving, the image is checked as a plain PNG of the fixed card size with no metadata chunk and no trailing bytes (a compromised page could still draw different pixels). The CSV is offered only for one associated account and contains times (as stored, with offset, and UTC), credit amounts as exact decimals, the reset time, fixed quality codes and a conflict flag, with `unknown` for anything missing; it holds no identifier, partition key or free text. The copied text is built by the extension from the same card, never by the page.

**Diagnostics.** **Cyclegauge: Copy Diagnostics** and CLI `--diagnostics` build a report in memory from an allowlist: versions, platform and architecture, SQLite availability, store state, whether locations are default or chosen, status and forecast tier, counts, a freshness bracket and fixed import codes. Anything not matching the allowlist becomes a fixed placeholder. No paths, identifiers, amounts or log content are included, and the extension command writes no file (an unsaved document plus the clipboard). CLI `--diagnostics` first performs the normal import into Cyclegauge's own store and writes nothing else. Review it before sharing. **Cyclegauge: Report a Problem** builds the same report and handling (unsaved document plus clipboard) and, only when you run it (from the command palette, the **Report a problem** button on Cyclegauge's own error notifications or the footer link in the credit view), opens the fixed address `https://github.com/StefanSuess/Cyclegauge/issues/new?template=bug_report.yml` in your browser with the editor's own opener. No diagnostics, identifier or other data is put in the address, Cyclegauge sends nothing itself (you decide whether to paste and submit anything on GitHub) and nothing is persisted.
