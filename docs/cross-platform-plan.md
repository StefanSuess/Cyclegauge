# Cross-platform readiness plan — 2026-10-13

Scope: implement the requested Windows/Ubuntu/macOS verification with one universal VSIX. No merge, release, telemetry, real-data fixtures or Kiro-owned SQLite access. Existing billing and collector contracts remain authoritative.

1. **Storage and portability.** Add a Windows-only owner DACL creation/verification path using Windows PowerShell/.NET (no native npm dependency). Never repair existing ACLs or create sensitive files before directory verification. Test permissive directories/files, inheritance, hard links, junctions, restart and actual collection. Keep POSIX checks unchanged. Unsupported ACL/filesystem/policy environments fail closed.
2. **One artifact, three hosts.** Extend existing CI to Windows x64, Ubuntu x64 and macOS ARM64. Keep the existing single candidate/rebuild verification. Run a pinned `@vscode/test-electron` host against the verified candidate payload, with isolated synthetic source/storage/profile. Check activation, command/webview creation, real SQLite persistence, watcher refresh, polling fallback, restart/deduplication and source immutability. Require all matrix jobs in promotion policy. No new publishing workflow or credentials.
3. **Evidence and native Kiro.** Investigate native Kiro test flags/distribution; document what generic VS Code does and does not establish. Record OS/architecture/host/Node versions and candidate digest. Do not declare Windows/Ubuntu production support without native Kiro evidence. Preserve protected manual promotion and exact-artifact acceptance.

Risks: Electron's embedded SQLite availability differs from standalone Node; ACL enforcement must reject reparse points and unsafe existing files without exposing SIDs/paths; watchers outside workspaces differ by host; native Kiro CI may lack a stable supported test/distribution interface. macOS Intel is a separate native verification gap when CI uses ARM64. Release publisher shell tests remain applicable to its Ubuntu runtime, not Windows extension compatibility.

Acceptance: `pnpm typecheck`, `pnpm test`, applicable release tests, synthetic fixture validator and diff checks; successful three-OS CI on the PR revision; independent read-only review before PR creation. Any unavailable environment or native verification remains an explicit blocker. Keep this as one focused PR while storage, host tests and promotion gates depend on each other; split unrelated work only if discovered.
