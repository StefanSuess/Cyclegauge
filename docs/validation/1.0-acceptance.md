# 1.0 acceptance checklist (maintainer, exact candidate)

One native test round on the **exact 1.0 candidate** that covers the "native test" and related exit criteria in [section 5 of the path to 1.0](../path-to-1.0.md#5-10-exit-criteria). It consolidates items that are otherwise scattered over [macos-acceptance.md](../macos-acceptance.md), [platform-verification.md](../platform-verification.md), [release-runbook.md](../release-runbook.md), the open lists in [wp6b](../wp6b-validation.md) to [wp6e](../wp6e-validation.md), [wp11-13-data-proof.md](../wp11-13-data-proof.md) and [wp10-hook-steering-design.md](../wp10-hook-steering-design.md). It does not replace them: where a procedure already exists, this file links to it.

Status: **a checklist, not evidence.** Nothing below has been run for 1.0. Record results in the release notes and, after publication, in [platform-verification.md](../platform-verification.md) via a pull request. Windows and Ubuntu results never imply each other or macOS; RHEL and macOS Intel stay unverified unless you test them.

## Rules (from AGENTS.md)

- Synthetic data only. Use an isolated instance made by `pnpm demo:setup` ([synthetic-demo.md](../synthetic-demo.md)): own user-data, extensions and storage folders, no sign-in, no Kiro agent, no real project opened, no real billing numbers in notes or screenshots.
- Never open your normal Kiro profile, logs, store or sessions, not even metadata. Session-hint items (M-S) need a Kiro session; create it only inside the synthetic profile with invented text, or stop and mark the item blocked.
- Everything here is a manual observation by the maintainer. Do not paste screenshots with paths, usernames or account names into issues or PRs.

## 0. Candidate and record

Do once per candidate. Stop on any mismatch.

- [ ] **0.1 Candidate is the right bytes.**
  - Setup: the CI run for the commit you intend to release (current `main` head, all required checks incl. attestation green). `mkdir -m 700 ~/cg-rc && gh run download <RUN_ID> --repo StefanSuess/Cyclegauge -n release-candidate -D ~/cg-rc`.
  - Steps: compute the SHA-256 (`shasum -a 256` on macOS/Ubuntu `sha256sum`, PowerShell `Get-FileHash -Algorithm SHA256`) of the candidate VSIX and compare with the run summary and `SHA256SUMS.txt`. Verify the attestation as the [release runbook](../release-runbook.md#5-verify-readiness-before-each-dry-run) describes (`ATTESTATION_VERIFICATION_FAILED` means: do not use this candidate).
  - Expected: all three digests are equal; the attestation matches the trusted workflow, `main` and the source commit.
- [ ] **0.2 Version and channel.** The VSIX `package.json` version is `1.0.0` (matching the `## 1.0.0` changelog section). Record: run id, commit, SHA-256, date.
- [ ] **0.3 Environments recorded.** Per platform: OS version and architecture, Kiro version (About), screen reader used. These go into the evidence entry.
- [ ] **0.4 Same VSIX everywhere.** The macOS, Windows and Ubuntu runs below all use this one file (compare the SHA-256 on each machine).

Per-machine setup used by every platform section (not a checklist item):

```sh
pnpm install --frozen-lockfile
pnpm demo:setup --open --vsix "path/to/candidate.vsix"
```

Install the printed `install-this.vsix` in the window titled **SYNTHETIC DEMO - not real usage**. The default demo pace (about 20 credits/day, limit 5000) never reaches the limit; for the warning, overage and right-sizing items create a demo variant with a higher invented pace (about 200 credits/day, as in the [demo script](../launch/demo-script.md)) or another synthetic anchor. Windows setup needs Windows PowerShell on a local NTFS drive. Create a fresh demo if more than 24 hours pass.

**Synthetic audit folder** (used by the audit items). Inside the demo's workspace folder, create these invented files; nothing real is copied:

| Item | Purpose |
| --- | --- |
| `synthetic-secrets/.env` and `synthetic-secrets/synthetic-key.pem` containing only the text `SYNTHETIC-NOT-A-SECRET` | secrets findings |
| `synthetic-data/synthetic-dump.sql` and `synthetic-data/synthetic-archive.zip`, each a few MiB of zero bytes | databases/archives and the size total |
| `synthetic-build/dist/` with a few files | build output |
| `node_modules/synthetic-pkg/index.js` | dependency folder entry |
| no `.kiroignore` at first | so findings read "Kiro may read this" |

Create large files with `dd if=/dev/zero of=… bs=1048576 count=N` (macOS/Ubuntu) or `fsutil file createnew … <bytes>` (Windows). Delete the demo folder when finished ([cleanup](../synthetic-demo.md#refresh-and-cleanup)).

### Workspace audit

- [ ] **M-5 Audit, size total and card.**
  - Setup: open the synthetic workspace folder with the audit files above.
  - Steps: run **Cyclegauge: Run Workspace Audit** (or **Run the workspace audit** in the Explorer's **Workspace Audit** view, or the title refresh button). Also check the view's welcome text: with no folder open it offers **Open Folder**, in an untrusted workspace **Manage Workspace Trust**, and the audit button only with a trusted folder.
  - Expected: a status line ("Checked HH:MM · N suggestions", its description "Kiro may read about N MiB"), then the group **Exclude from Kiro** ("adds lines to .kiroignore"; its tooltip says "Nothing changes until you save."; no note row inside). Every group and sub-group is **collapsed** when the view first shows the results and keeps your open/closed choice after a refresh. The sub-groups hold secrets, databases/dumps, archives, build output and dependencies, largest first, each item marked "Kiro may read this"; the size matches the invented large files (nested files not counted twice); the credit view's **Workspace check** card shows the item count and the size, with no path or folder name; wording calls it exposure, never a saving.
- [ ] **M-6 Exclude flow.**
  - Steps: click **Exclude from Kiro…** (the diff icon) on one finding. First note whether `kiroAgent.agentIgnoreFiles` lists `.kiroignore`: if it does not (empty or other files), **Expected:** the Exclude group reads "won't take effect yet — add .kiroignore to Agent Ignore Files" with a warning icon, its first row **Add .kiroignore to Agent Ignore Files…** opens the setting, and there is no separate top-level "turned off" or "isn't active yet" row; after **Apply** the notice adds "Kiro uses .kiroignore only when it's listed in Agent Ignore Files." with **Open setting**. **Expected native behaviour:** the editor's refactor preview opens with one change labelled "Exclude from Kiro" and its description (why and the alternative "Hide this item"); press **Apply**, then read the opened `.kiroignore` (unsaved, root-anchored line, notice "Changes prepared in 1 file — review and save."); before saving, the item reads "prepared — save the file to apply" (distinct icon) and the status line adds "· 1 file with unsaved prepared changes"; save it yourself and the marks disappear (closing or reverting without saving removes them too). Repeat with **Discard** (nothing changes; "No changes were made." at most). **Record** if Kiro applies the edit without showing a preview, or shows no description: the edit is still unsaved, but the confirmation step is then not provided by the editor. Repeat once with the check mark on the **Exclude from Kiro** group. Add `.kiroignore` to Agent Ignore Files (`kiroAgent.agentIgnoreFiles`) if the group says it won't take effect, then wait about a second after saving: the audit re-checks and the group no longer shows that warning. Do the same once for a Steering or Hook item (**Load only when needed** or **Run only manually**): after **Apply** it reads "prepared — save the file to apply"; after you save that file the Steering and Hooks review runs once by itself and the item disappears from its group (with the automatic review off, no other save starts the Steering and Hooks review; saving an ignore file still re-checks the audit).
  - Expected: the entry reads "prepared — save the file to apply" before saving; after saving (with `.kiroignore` listed in Agent Ignore Files), the check re-runs silently, the item is no longer listed as readable, the size total drops, and the card updates. **Copy .kiroignore lines** (group right-click menu), **Hide this item** and **Show hidden items again** each behave as in [usage.md](../usage.md#workspace-audit). With `files.autoSave` on, the lines open in a separate tab instead.
- [ ] **M-7 Audit reminders and re-check.** Run **Cyclegauge: Reset Workspace Audit Reminder** and reload: one prompt for the never-audited workspace; **Later** snoozes. Set `cyclegauge.auditAutomatically` to `onOpenAndChanges`, reload, create a new matching file (for example `synthetic-extra.sqlite`): the audit refreshes without a notification and the item appears.

## 4. Release and channel checks (maintainer, once per candidate)

- [ ] **R-1 Stable channel: 1.0.0 builds without the pre-release flag.**

  - Steps: inspect the VSIX manifest (unzip into a fresh empty directory and read `extension/package.json` and `extension.vsixmanifest`) and the GitHub/Open VSX plan in the release-workflow **dry run** (`dry_run = true`, version `1.0.0`; see the [runbook](../release-runbook.md#dry-run-safe-no-writes-no-environment-no-secrets)).
